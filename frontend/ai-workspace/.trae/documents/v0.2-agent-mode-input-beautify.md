# V0.2 — Agent 模式 + 输入框美化 实施计划

## Context

V0.1 已完成基础 AI Chat（流式对话、会话管理、JWT 鉴权）。V0.2 目标是根据设计文档和设计图，在现有 Chat 页面上扩展 Agent 能力：

1. **输入框美化**：当前输入框只有一个不明显的回形针图标，用户无法直观发现文件上传入口。需改为设计图中醒目的"+"按钮，带"上传文件"标签。
2. **真实文件上传**：当前"上传"只是在本地添加 chip，未真正上传。需调用 `POST /files/upload` 获取 `file_id`，发送消息时携带。
3. **Chat / Agent 模式切换**：通过左侧菜单 Agent 入口进入 Agent 模式（`/agent` 路由，复用 Chat 页面组件）。
4. **Agent 执行 UI**：Agent 模式下展示执行步骤（绿色对勾）、工具调用卡片，由 SSE 事件驱动。

设计文档核心约定：Chat 与 Agent 共用页面，`Conversation.type` 区分模式，Agent SSE 事件类型包括 `agent_start` / `text` / `tool_start` / `tool_result` / `done`。

## 实施步骤

### 1. 路由 — `src/router/index.ts`

- 在 AppLayout children 中新增 `/agent` 路由，指向同一 Chat 组件：
  ```ts
  { path: 'agent', name: 'Agent', component: () => import('@/views/chat/index.vue') }
  ```
- **修复鉴权守卫**：当前守卫只保护 `/workspace`，`/chat` 和 `/agent` 未被保护。改为保护所有 AppLayout 路由（`/workspace`、`/chat`、`/agent`），未登录统一跳 `/auth`。

### 2. 类型与 API — `src/api/conversation.ts` + 新建 `src/api/file.ts`

**conversation.ts 扩展：**
- `ConversationCreate.type`: `'chat'` → `'chat' | 'agent'`
- `Conversation.type`: `'chat'` → `'chat' | 'agent'`
- `itemsType`: 新增 `type: 'chat' | 'agent'` 字段（让侧边栏能按类型过滤）
- `getRecentConversations`: query 参数新增可选 `type`，按类型拉取会话列表
- 新增 `sendAgentMessageStream(conversationId, content, fileIds?, tools?)`：复用 `stream()` 底层，但解析 Agent 事件类型，yield 结构化事件：
  ```ts
  type AgentEvent =
    | { type: 'agent_start' }
    | { type: 'text'; content: string }
    | { type: 'tool_start'; tool: string; arguments?: Record<string, unknown> }
    | { type: 'tool_result'; tool: string; status: 'success' | 'error'; result?: unknown }
    | { type: 'done'; message_id: number }
  ```

**新建 file.ts：**
- `uploadFile(file: File, onProgress?)`：调用 `request.ts` 已有的 `upload('/files/upload', file, 'file', { onProgress })`，返回 `{ id, name, size, url }`

### 3. Chat Store — `src/stores/chat.ts`

- `ChatSession` 接口新增 `type: 'chat' | 'agent'` 字段
- `createSession(title, type = 'chat')`：传入类型，创建对应类型会话
- `fetchRecent(type?)`：新增可选 type 参数，按类型拉取会话列表
- 新增 `currentMode` computed：优先从 `currentSession?.type` 推导，回退到路由判断
- 模式切换时重新拉取对应类型的会话列表

### 4. 侧边栏 — `src/components/layout/AppSidebar.vue`

- Agent 导航项 path: `/agents` → `/agent`
- `isChatPage` → `showSessionList`：在 `/chat` 和 `/agent` 页面都显示会话列表
- **模式感知会话列表**：进入 `/chat` 拉取 type=chat 会话，进入 `/agent` 拉取 type=agent 会话
- `onNavClick`：点击 Agent 时也执行 `selectSession(null)` 重置到欢迎态
- `onSelectSession`：根据会话 type 跳转对应路由（chat 会话→`/chat`，agent 会话→`/agent`），保持路由与会话类型一致
- watcher 重命名并按模式重新拉取

### 5. 输入框美化 + 文件上传 — `src/views/chat/index.vue`

**输入框重构（对照设计图）：**
- 将单行 `<input>` 改为 `<textarea>`（支持多行，auto-resize）
- 左侧醒目"+"按钮（32px 圆形，比当前回形针更突出），点击触发文件选择
- "+"下方显示"上传文件"文字标签
- Agent 模式下额外显示"选择工具"按钮（popover/dropdown，可勾选 calculator / excel_analysis / chart_generator）
- 右侧蓝色"发送"按钮（保持现有样式）
- placeholder 按模式变化：
  - chat: `"输入你的问题..."`
  - agent: `"请输入你的问题，或上传文件让 Agent 帮你分析..."`

**真实文件上传：**
- Attachment 结构扩展：新增 `file_id?: number`、`status: 'uploading' | 'done' | 'error'`、`progress?: number`
- `onFileChange`：选文件后立即调 `uploadFile()`，chip 显示上传进度
- 上传完成后回填 `file_id`；失败标记 error 并允许重试/移除
- `onSend` 守卫：若有附件仍处于 uploading 状态，禁用发送并提示"文件上传中..."

### 6. Agent 执行 UI — 新建组件 + Chat 页面集成

**新建 3 个组件：**

- `src/components/chat/AgentMessageBubble.vue` — Agent 助手消息整体包装器，组合 steps + tool cards + 文本内容，替代 agent 模式下的普通 bubble 渲染
- `src/components/chat/AgentSteps.vue` — 执行步骤列表，每步显示 label + 状态图标（✅ done / ● running spinner / ○ pending）
- `src/components/chat/ToolCard.vue` — 工具调用卡片，显示工具名（带图标）、状态（运行中/成功/失败）、参数预览（key-value 展示，非裸 JSON.stringify）

**ChatMessage 数据结构扩展：**
```ts
interface AgentStep { id: number; label: string; status: 'pending' | 'running' | 'done' }
interface ToolInvocation { id: number; tool: string; status: 'running' | 'success' | 'error'; arguments?: Record<string, unknown>; result?: unknown }
interface ChatMessage {
  // 现有字段...
  steps?: AgentStep[]
  tools?: ToolInvocation[]
}
```

**Agent SSE 处理逻辑（runReply 分支）：**
- Agent 模式下 `runReply` 调用 `sendAgentMessageStream` 而非 `sendMessageStream`
- 预占位 assistant 消息带 `steps: []`、`tools: []`
- `agent_start` → 初始化步骤列表
- `text` → 追加到 `content`（打字机效果不变）
- `tool_start` → push 新 ToolInvocation（status: running）
- `tool_result` → 更新对应 ToolInvocation 状态（按 tool 名 + 顺序匹配）
- `done` → 设置真实 `message_id`，标记完成
- **中断处理**：用户 abort 时，将运行中的 tool 卡片标记为 'stopped' 而非永久 spinner

### 7. 模式感知的欢迎态 & onRegenerate 分支

- **欢迎态**：Agent 模式下使用不同的 suggestion cards（Excel 分析、图表生成、报告生成），文案强调 Agent 能力
- **onRegenerate**：Agent 模式下走 `sendAgentMessageStream`，splice 时清除旧消息的 steps/tools
- **loadMessages**：Agent 会话历史消息若后端返回 steps/tools 元数据则还原；否则按纯文本渲染（后端契约待确认，前端先做兼容处理）

## 验证方式

1. **启动开发服务器**：`npm run dev`（或 `pnpm dev`），访问 `http://localhost:5173`
2. **输入框美化验证**：
   - 进入 `/chat`，确认输入框有醒目"+"按钮、"上传文件"标签、蓝色发送按钮
   - placeholder 文案正确
3. **文件上传验证**：
   - 点击"+"选择文件，确认 chip 显示上传进度
   - 上传完成后 chip 显示 file_id；上传中发送被禁用并提示
4. **Agent 模式验证**：
   - 点击侧边栏 Agent，跳转 `/agent`，显示欢迎态（Agent 专属建议卡）
   - 侧边栏会话列表切换为 agent 类型会话
   - 输入消息发送（若后端 Agent API 就绪），观察执行步骤和工具卡片渲染
   - 若后端未就绪，错误提示正常弹出
5. **模式一致性**：
   - 在 /agent 页面点击 chat 类型会话 → 自动跳转 /chat
   - 在 /chat 页面点击 agent 类型会话 → 自动跳转 /agent
6. **中断验证**：Agent 执行中点击停止，tool 卡片状态合理（非永久 spinner）
